- 보드는 **배너 1개**(제목·2줄 설명·[보드 열기])로만 노출되며 위치가 프로세스 설명 바로 아래 —
  "카테고리 정하고 → 보드에 쓰고 → 지식문서" 순서와 어긋남. 보드 내부 상태(검토 대기 수 등)는 표시 없음.
- ProcessGuide 3단계가 **"사용가이드"**로 되어 있어 보드(B1~B4, 8/29 완결)가 프로세스 설명에 없음.
  `guide.noteSource`("직접 쓰거나·카탈로그·CSV — 넷 다 같은 곳")는 보드 도입 전 문안.
- 사용법 가이드 카드는 **모든 테넌트에 항상 표시**. 설계 당시(PLN-260807 D3) "카탈로그 없어도 가이드는
  쓴다 → 숨기지 않는다"로 결정했으나, 실제로는 쇼핑몰(상품 유형별 사용법)에만 의미 있는 기능.

## 4. 제약·결정

- **D-1 동기화(Sync)는 섹션이 아니라 소스 행의 동작**이다 — 4단계 설명의 ②에 대응하는 카드는 없다.
  설명 카드의 ②는 소스 카드로 스크롤하고 "각 소스 행의 [동기화]" 문안으로 안내한다.
- **D-2 플래그 저장처 = `tenants` 컬럼**(JSON 설정 묶음 신설 안 함): 위젯 설정·스토어프런트와 같은
  패턴(컬럼 1개 + 전용 GET/PATCH + 감사). 플랫폼 어드민 애드온 축이 아닌 이유: 과금·서버 판정 대상이
  아니고 운영자가 스스로 켜고 끌 수 있어야 한다. 어드민 노출은 범위 밖(필요 시 후속).
- **D-3 게이트 OFF여도 데이터는 보존**: 유형·가이드 문서·RAG 인용 로직은 그대로(카드만 숨김).
  이미 작성된 가이드가 있으면(현재 0건) 마이그레이션이 플래그를 1로 세운다 — "보이지 않는 폴백" 금지.
- **D-4 인박스 2종은 순서 밖**: 지식 공백 제안·답변 제안은 내용이 있을 때만 뜨는 주의 요구 요소.
  프로세스 순서에 끼우면 평소엔 빈 자리가 되므로 현 위치(상단/소스 아래) 유지.
- **D-5 우측 KB 질의 패널·문서 상세 유지** — 이번 범위는 좌측 컬럼 순서와 설명.
- 스테이징 `DB_SYNCHRONIZE=false` → SQL 선적용 + `npm run migrations:manifest` 필수.

## 5. 검토 제안 (요청 R5)

1. **단계 번호를 카드 제목에 붙이고 설명 카드에서 클릭 이동** — "① 소스 ② 동기화 ③ 보드 ④ 지식베이스문서"와
   카드 "① 소스 / (옵션) 사용법 가이드 / 카테고리 / ③ 보드 / ④ 지식베이스문서"가 같은 번호로 묶이면 설명과
   화면이 하나로 읽힌다. 카테고리·가이드는 번호 없이 "설정" 성격으로 표기(§4 D-1과 일관).
2. **보드 카드에 상태 한 줄**: "검토 대기 N건 · 채택 M건" — 운영자가 보드에 들어가야 하는 이유를 페이지에서
   바로 보게 한다(신규 API 없이 목록 endpoint total 2회 조회). 채택 M은 KB 목록 `source=board` 뱃지와 동일 축.
3. **설명 카드에 "그 외 경로" 각주 유지**: 직접 추가·카탈로그 동기화·CSV는 보드를 거치지 않는 정상 경로
   (REQ-260829 D-4 product 예외)이므로 숨기지 말고 "보드를 거치지 않는 빠른 길"로 명시 — 안 그러면 카탈로그
   2,078건이 "보드 없이 어떻게 들어왔나"가 된다.
4. **소스 카드 힌트 문안을 보드 기준으로 갱신**: 현재 "동기화 전에는 지식이 되지 않는다 — 한 번만 가져오면
   [지식베이스문서 추가]가 더 빠르다"를 "한 번만 가져오면 보드에 작성이 더 빠르다"로.
5. **(선택, 이번 범위 밖) 프로세스 설명 접힘 상태를 테넌트 최초 진입 시엔 펼침 고정** — 현재 localStorage
   키 1개라 브라우저별로만 기억. 유지.
