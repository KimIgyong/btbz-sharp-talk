# SharpTalk for Go2Joy — Requirements Analysis (요구사항 분석서)

## 1. Project Overview (프로젝트 개요)

- **Project**: SharpTalk for Go2Joy — 숙박 도메인 특화 AI 상담원
- **Stage scope**: Stage 1 (파트너) · Stage 2-A (예약 전 게스트) · Stage 2-B (예약 후 호텔 리셉션)
- **Upstream artifacts**: `SHARPTALK-G2J-AGENTCAT-1.2.0` (에이전트 카탈로그), Hotel Admin 영상 가이드 51편 분석, Stage 1·2 상담 시뮬레이션 12 시나리오
- **Terminology**: Stage / Phase / Sprint 3축 — 카탈로그 §0.1 준수

### 1.1 Background and Purpose (배경 및 목적)

Go2Joy는 베트남 시간제 숙박 예약 플랫폼으로 약 5,500개 제휴 숙박업체를 운영한다. 파트너 상담(정산·예약·요금)과 고객 상담(검색·체크인·투숙 중 요청)이 모두 사람 손에 의존하고 있으며, 특히 **정산 이의제기 기한**과 **예약 취소 사유 선택**처럼 오판이 곧 금전 손실로 이어지는 업무가 상담 품질에 좌우된다.

본 프로젝트는 이 업무를 AI 상담원으로 대체하되, **AI가 대신 눌러서는 안 되는 조작**과 **답해서는 안 되는 정보**를 요구사항 수준에서 명시하는 것을 목적으로 한다.

### 1.2 Expected Benefits (기대 효과)

| 관점 | 효과 |
|------|------|
| 파트너 | 정산 기한 누락으로 인한 손실 방지, 취소 사유 오선택 방지, 24시간 자가 해결 |
| 게스트 | 예약 전 조건 확인 이탈 감소, 무인 시간대 체크인 지원, 투숙 중 요청 즉시 접수 |
| Go2Joy | CS 인입 감소, 파트너 리텐션, 광고·부가상품 판매 접점 확대 |
| 아메바 | Stage 1 광고 인벤토리 영업권 회수 경로 확보, Stage 2-B 테넌트 서비스 사업화 |

### 1.3 Derivation basis (도출 근거)

본 요구사항은 **추상적 기획이 아니라 12개 실제 대화 시나리오에서 역산**했다. 각 FR은 최소 하나의 시나리오(SC) 또는 콘솔 관찰 사실에 대응하며, 대응이 없는 FR은 두지 않는다.

## 5. Constraints and Assumptions (제약사항 및 가정)

### Constraints

| ID | 제약 |
|----|------|
| C-01 | Hotel Admin UI가 v0.4.1~v0.12.0으로 파편화되어 있어 KB가 버전별로 갈린다 |
| C-02 | 기존 Notion 가이드에 화면과 어긋나는 항목이 7건 확인되었다. 정제 없이 RAG 소스로 쓸 수 없다 |
| C-03 | 이의제기 사유는 시스템에 2종, 취소 사유는 11종으로 고정되어 있다. 에이전트가 사유를 새로 만들 수 없다 |
| C-04 | 예약 유형별 시간대(`Qua đêm` 22:00→익일 12:00, `Theo ngày` 13:00→익일 12:00)는 시스템 고정값이다 |
| C-05 | 파트너 권한은 `Quản lý` / `Lễ tân` 2종뿐이다. 세분화된 권한을 전제할 수 없다 |
| C-06 | 광고 캠페인은 현재 무료 체험 버전이며 발송 대상 3종이 미출시(`Sắp mở`)다 |

### Assumptions

| ID | 가정 | 검증 이슈 |
|----|------|-----------|
| A-01 | `Chat với khách` / `Tin nhắn từ G2J` 채널에 API·웹훅으로 접근할 수 있다 | **OQ-011 (BLOCKER)** |
| A-02 | 예약·객실 상태를 실시간 조회할 수 있고, 일부 쓰기가 가능하다 | **OQ-001 (BLOCKER)** |
| A-03 | 기존 리스팅 데이터로 호텔별 오버레이를 자동 생성할 수 있다 | OQ-004 |
| A-04 | 에이전트의 쓰기 권한 범위가 합의되어 있다 | OQ-012 |
| A-05 | 스탬프(`tem`) 프로그램의 요금 영향 규칙을 확보할 수 있다 | OQ-013 |

> A-01과 A-02가 부정되면 각각 Stage 1과 Stage 2-B의 요구사항 절반 이상이 「안내 전용」으로 축소된다. Phase -1 게이트에서 반드시 확정한다.

## 7. Success Metrics (성공 지표)

| KPI | Measurement | Target (Stage 1 기준) |
|-----|-------------|----------------------|
| 자가 해결률 | 이관 없이 종료된 대화 비율 | ≥ 60% |

| 근거 없는 단정 응답 | 감사 샘플링 기준 | **0건** |
| CS 인입 감소 | Go2Joy CS L2 티켓 수 | −30% |
| 응답 만족도 | 대화 종료 CSAT | ≥ 4.2 / 5 |
