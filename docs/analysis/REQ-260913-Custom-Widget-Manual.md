## 4. 사용자 흐름 (문서가 따라갈 순서)
```
[0] 개념: 기본 위젯 vs 커스텀 위젯 ── 무엇이 어디서 정해지나
      │
[1] 준비: 디자인 파일 업로드 (폰트·아이콘) ── 규격 확인 → 파일 추가 → 공개 URL
      │
[2] 만들기: [커스텀 위젯 만들기] ── 이름·폰트·글자 크기·모서리·패널 크기·런처 아이콘·메모
      │        └ 편집기 간이 미리보기 → [보관함에 저장] / [저장 후 사용함]
[3] 확인: [미리보기] ── 실제 위젯을 10분 토큰으로 열어 확인 (고객 무영향)
      │
[4] 적용: [사용함] ── 즉시 반영, 배포 없음 · [기본 위젯으로 복귀]
      │
[5] 운영: 복제 → 편집(사용 중이면 경고) · 이력 복원 · 보관/삭제 · 패키지 내보내기/가져오기 · 설정 스냅샷
      │
[6] 확장(선택): 정제 CSS ── 어드민 애드온 ON → CSS 입력 → [검사] → 저장
```

## 5. 제약·전제
- 문서는 **코드 기준**으로 작성(현행 라벨·한계값: 글자 13~16px, 패널 360~480×480~720, 모서리 8/12/16px, 폰트 2MB·아이콘 256KB·512px·이미지 2MB·2000px·시안 10MB, 디자인 영역 상한 50MB, CSS 32KB).
- en/vi는 AI 번역 초안 표기(기존 notice 유지). 한국어가 원본.
- html은 생성기가 없으므로 02 매뉴얼 템플릿(스타일·pagenav·toc·callout)을 복제해 수작업 작성 — md와 html의 내용 동기화 책임은 작성 시점.
- 캡처는 로컬 dev 콘솔(ivyusa 데모 테넌트)에서 만들며 실제 고객 데이터 없음. 어드민 애드온 모달 캡처는 로컬 admin@로 가능.
- 스키마·API 변경 없음 → PR에 Migration 섹션 불필요. `/manual` 카드는 정적 html이라 콘솔 빌드 영향 없음(web 컨테이너 재빌드는 배포 스크립트가 수행).
